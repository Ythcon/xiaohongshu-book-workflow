# 小红书建筑书籍内容生产工作流

> 一个面向建筑、城市与设计书籍的内容生产 Skill：把一本专业书，整理成一组读者能看懂、团队能复用、发布时有依据的小红书图文内容。

## 我具体在做什么

- 为建筑、城市、设计类书籍和专业刊物策划小红书选题。
- 从一本书中提炼一个清晰命题，避免把内容做成资料堆砌。
- 将核心观点拆成 6–10 张连续的 3:4 竖屏图卡。
- 为每个案例寻找真实、可说明出处的图片，并记录来源与许可证。
- 产出标题、卡片文案、发布文案、图片来源说明和结构化清单。
- 根据发布后的数据复盘封面命题、内容节奏和收藏价值。

## 最终保留的两个 Skill

### [xhs-designer-single-book](skills/xhs-designer-single-book/SKILL.md)

建筑师、设计师或设计理论家的单本书籍工作流。负责锁定书籍论点、挑选 4 个证据案例，并生成 6 张有完整叙事的图卡。

### [xhs-quick-book-cards](skills/xhs-quick-book-cards/SKILL.md)

建筑书籍与建筑杂志的快速图卡工作流。书籍采用 6 页，杂志采用 8 页，重点是快速压缩命题、案例和来源记录。

## 完整流程

```text
选题查重 → 书目与内容研究 → 图片检索与来源记录
        → 提炼核心命题，拆解案例 → 生成 3:4 图卡
        → 人工检查 → 整理发布文案与结构化文件
        → 按需要选择少量案例上传并归档
```

### 1. 选题与查重

每次选书前先检查 [`book_registry.json`](book_registry.json) 和 [`已做书单.md`](已做书单.md)：

- 先查书名，命中即更换选题。
- 如果要求“未提过的建筑师”，设计师命中也视为重复。
- 完成最终 QA 后，再登记作者、书名、成品位置和完成状态。

### 2. 研究与图片来源

按照两个 Skill 中的研究与来源规范整理书目信息、项目资料和公开图片。图片不只保存文件，还要留下出处、页码、链接或许可证说明，写入每套内容的 `图片来源.md`。

### 3. 内容拆解

每本书先回答一个问题：**这本书最值得读者记住什么？**

再按“主线 → 观点 → 案例 → 总结”的顺序组织卡片。每个案例包含名称、基本信息、它如何支撑核心命题、一句移动端标题和一段简短解释。

### 4. 图卡生成

Skill 自带的 `render_post.py`、`render_utils.py` 和验证脚本使用 Python 与 Pillow 生成 1242 × 1660 的 3:4 JPG，同时保留 `preview.jpg`、卡片图片和结构化 JSON。

### 5. 质检与发布准备

发布前人工检查真实书封、文字溢出、图片裁切、图文关系、来源许可证和案例数量。

上传时**不需要把全部内容一次性上传**。通常从一套内容中选择 3–6 个最能支撑主题的案例即可，剩余案例留作后续发布或资料归档。

## 一个实际案例：Casabella 100

**核心问题：**建筑形式应该从哪里长出来？

**核心命题：**场地决定形体，程序组织空间，公共生活检验建筑是否真正成立。

围绕这个命题，内容被拆成 6 个案例：

1. Luigi Cosenza：现代建筑不是一种外观，而是解决具体生活的工具。
2. Villa Oro：顺着坡地展开，比复制标准平面更重要。
3. Un Tennis：既有球场是建筑秩序的起点。
4. Ponte di Casanova：庭院组织学校的公共生活。
5. Bexhill Casino：连续流线把文化建筑连接到海岸公共空间。
6. 总结：场地条件、空间秩序与生活方式共同生成建筑。

实际上传时可以只选其中 3 个案例，保持主题集中；完整 6 个案例仍保留在本地归档中。

## 交付物

```text
output/<内容 slug>/
├── preview.jpg          # 整套内容预览
├── 01.jpg ... 06.jpg    # 3:4 图卡
├── 发布文案.md           # 标题、正文、话题与发布备注
├── 图片来源.md           # 图片出处、许可证与书目信息
└── post.json            # 案例、命题、页序等结构化数据
```

仓库只保留两套最终 Skill 及其必要的参考文档和验证脚本；书目登记、查重与来源规范作为项目说明材料一并保留。具体书籍的临时抓取脚本、批量生成脚本和下载资料不放在公开仓库中。

## 我的工作方法

### 专业内容，先理解再表达

先建立书籍的观点框架，再决定标题、案例和图片，而不是先做一张好看的封面。

### 效率来自结构化

把研究、文案、图片、排版和质检拆成固定步骤；脚本负责重复劳动，人负责判断和取舍。

### 自动化有边界

模型可以辅助抽取、分类和改写，图片仍由本地流程生成；发布必须经过人工确认，不模拟登录，不保存小红书密码。
